# 极简播放器 · 滑动与进场的闪屏（v1.3.122 / versionCode 145）

基线：`5a533c5`（v1.3.121 / 144）。本轮只改极简页的**绘制成本**与**封面首帧**，不动播放内核、
歌词解析、MediaSession、背屏、原歌词舞台，也不改版式。

---

## 一、现象

两处，都是"闪"，不是"卡"：

1. 封面页与歌词页左右手势切换时，整屏闪一下；
2. 刚进入播放页（从迷你播放条展开）的瞬间闪一下。

两条线索很重要：

- 用户在 1.3.119 / 1.3.120 没有报过这个现象，报的是 1.3.121；
- 两个现象都发生在"整页大面积重绘"的时刻。

## 二、先确认这不是"某一帧白屏"

`dev/probes/flickerMinimal.mjs` 用 CDP screencast 逐帧录制（静止 / 左右滑动 / 点圆点 /
120 行长歌词 + CPU 降速 6× / 冷启动进入），每帧用 sharp 解码成 72×156 灰度，逐帧比对亮度、
方差和与前后两帧的偏差，判定"单帧白屏、黑屏、亮度突变"。

**在 Chromium 里一帧也没抓到。** 这条阴性结果本身就是信息：如果丢的是一整帧内容，screencast 一定
会把它录下来。所以这不是"某一帧画错了"，而是**每帧的开销超过了帧预算**——真实设备上合成器来不及，
就会把上一帧或底色顶上去，人眼看到的是闪。于是换一个可量化的方向：量每帧到底花了多少。

## 三、测量（CDP Performance 计数器）

`dev/probes/swipeCost.mjs`，393×852 @2.75dpr，一次 12 步的 CDP 真实触摸滑动：

| 场景 | 指标 | 1.3.121 | 1.3.122 |
| --- | --- | --- | --- |
| 封面页滑动 | 样式重算 | 61 次 / **102ms** | 60 次 / **25ms** |
| 封面页滑动 | 布局 | 32 次 / 19ms | 20 次 / 15ms |
| 封面页滑动 | 主线程总计 | 182ms | 97ms |
| 歌词页滑动 | 样式重算 | 41 次 / **76ms** | 41 次 / **2ms** |
| 歌词页滑动 | 主线程总计 | 105ms | 27ms |
| 换一次调色板（700ms 渐变） | 样式重算 | 51 次 / **371ms** | 34 次 / **19.7ms** |
| 换一次调色板（700ms 渐变） | 主线程总计 | 449ms | 322ms |

注意这次测量只在**219 个元素 / 91 个逐字 span** 的演示歌词上做。真实歌曲的歌词页是几千个 span，
样式重算的代价随节点数线性增长——也就是说上面 102ms 那一栏，在真机上是它的数倍。

## 四、原因

### 1. 背景颗粒用了 `mix-blend-mode`（1.3.121 新增）

```css
.min-amb__grain { opacity: .05; mix-blend-mode: overlay; }   /* 旧 */
```

混合模式会把 `.min-amb` 这一整摞（wash + 3 个 blob + bloom + veil + vignette）变成**混合组**：
合成器要为它单独持有一块离屏 surface，并且只要下方或上方有任何东西重绘，就要重新混合整屏。
滑动时条带每帧都在重绘，于是每一帧都是一次全屏混合。

### 2. 滑动位置被当作"外壳上的自定义属性"广播（1.3.121 新增）

```js
shellRef.current.style.setProperty('--min-pos', String(pos));   // 旧
```

`--min-pos` 没有用 `@property` 注册，对引擎来说是一串**不透明的 token**。它挂在 `.min` 上、
`inherits: true`，所以每改一次，**整棵 DOM 都要重算样式**——包括歌词页的每一个字。CSS 侧有四条
规则读它（条带 transform、袖套视差、两处淡出、圆点宽度）。一句话：一次滑动 = 60 次全页样式重算，
其中 20 次还因为圆点改 `width` 顺带跑了一遍布局。

### 3. 调色板渐变挂在外壳上（1.3.119 起，但成本被 1.3.121 放大）

```css
.min { transition: --min-base 700ms, --min-field-1 700ms, ... }   /* 旧 */
```

打开播放页时，页面先用主题色挂载，封面取色落定后再渐变过去（换歌同理）。这五个变量是**继承**的，
渐变就跑在 `.min` 上：700ms 内每帧重算整页样式。1.3.121 把背景从 2 层渐变加到 4 层、还叠了混合
模式，于是同一段渐变每帧要多重绘一整屏——这就是"刚打开就闪"的时间和位置都对得上的地方。

### 4. 封面 `<img>` 挂载时位图还没解码（`MinimalArtwork`）

```js
const [stack, setStack] = useState(() => (url ? [url] : []));   // 旧
```

初始 state 直接把 url 塞进栈，于是 `<img>` 一挂载就是 `opacity: 1`，但位图还没解出来——那一帧
袖套是一块空板，图随后"啪"地出现。这是全屏最大的一个元素，它跳一下就是一次闪。

### 5. 懒加载 chunk + `fallback={null}`

`MinimalStage` 是 `lazy()` 的，而 `ownsMinimalStage` 为真的同一帧里 visualizer 已经被卸载、
下面的首页也在 350ms 后 `display: none`。chunk 没就绪的那一两帧里，播放页**什么都不画**，
露出的是 `html` 的 `#09090b`（浅色主题下就是一次黑闪）。

## 五、改法

| # | 改动 | 文件 |
| --- | --- | --- |
| 1 | 去掉颗粒的 `mix-blend-mode`，改用普通 alpha（0.046 / 浅色 0.03） | `minimalStage.css` |
| 2 | 条带位置改为**直接写样式**到用到它的 4 个元素；不再广播 `--min-pos` | `MinimalStage.tsx`、两个页面组件 |
| 3 | 圆点改用 `::before` + `transform: scaleX()`，布局盒固定 16px，不再每帧改宽度 | `minimalStage.css` |
| 4 | 调色板渐变移到 `.min-amb`（8 个 span），外壳上的 5 个变量改为静态 | `MinimalAmbience.tsx`、`minimalStage.css` |
| 5 | 封面栈从空开始：先解码，再插入，再逐帧抬 opacity（真交叉淡入） | `MinimalArtwork.tsx` |
| 6 | 用 App 已有的空闲队列预热 chunk | `AppOverlays.tsx` |

几处细节：

- **圆点的几何完全没变**：旧的是 `width: 4px + 4px * --near`，新的是 8px 的胶囊 `scaleX(.5 → 1)`，
  停在哪一端都是 4px / 8px；`margin: -6px` 让布局盒仍是 4px，触摸区仍是 16px。
- **视差没变**：仍是 `pos * 11%`（含回弹时的越界值），只是从 CSS 变量改成内联 transform，并给
  `.min-cover__stage` 加 `will-change: transform`——拖动时它每帧都在动，不提升就会每帧重绘那张封面图。
- **`prefers-reduced-motion` 下** `.min-amb` 也取消过渡，换色直接切。
- 外壳上仍然保留那 5 个变量（袖套光晕、当前行染色、已唱字色要用），只是不再承担渐变。

## 七、没有验证的，以及残留风险

- **没有真机、也没有模拟器镜像**。本轮所有数字来自 Chromium（headless，软件光栅）：
  Media3 播放、锁屏/后台、背屏与 LSP、Compose 图层顺序、真实 inset、手感与帧率、功耗、
  50 首连播、Activity 重建，全部未验证。
- 本机是软件光栅，渐变重绘比真机 GPU 贵。上面"主线程 322ms / 700ms"这一栏在真机上应显著更低，
  但**换色仍要重绘 4 层全屏渐变**，这是设计本身决定的：如果真机上换歌仍有可感知的掉帧，下一步是把
  调色板渐变改成"旧环境层淡出 + 新环境层淡入"的两层透明度交叉（纯合成，零重绘），而不是继续压
  样式重算。
- 进场时入场动画（420ms）与调色板渐变（700ms）仍然是重叠的。没有把它们错开：错开会让背景比封面
  晚半拍变色，视觉上更奇怪。
- 颗粒从 `overlay` 改成普通 alpha，理论上在极暗底色上的对比会略低一点；像素对比显示平均差 1/255，
  肉眼不可分。

## 八、构建

APK 体积从 68.5MB 降到 51.5MB，原因不是这次改动：`android/app/src/main/assets/public` 里积了 649 个
历史构建的哈希文件（14.9MiB），每次 `cp -rf` 覆盖式同步都不会删旧的。这些文件没有任何入口引用
（`index.html` 只引用当前哈希），已清掉。清理脚本只删"名字形如 `name-HASH.js/css/map` 且当前
`dist/` 里没有"的文件，`cordova.js` / `cordova_plugins.js` 一并保留。
