# 音乐身份与搜索结果合并

版本 1.5.63 / 278；分支 feat/library-search-v2；S3.2 基线 bc1334f8（实施提交由 Git log 查询）。

## 身份依据

- 队列、收藏及播放继续使用 getPlaybackSongKey 的来源 + 原歌曲 ID。平台 ID 碰撞不会覆盖另一来源。
- sourceSongMap 统一同来源重复项处理，保留最后值。推荐引擎仅复用这一等价工具，评分、雷达策略不变。
- 原平台 QQ mid、酷狗合法文件 hash 可作为平台目录证据；其他来源携带的歌词匹配 ID 不作为录音证据。当前没有经过验证的跨平台 ISRC 或录音关联生产者。
- 元数据合并要求完整同名、全部同名歌手、同专辑、有效时长且任意成员差值不超过 1000ms；缺失/未知信息、同平台不同 ID、舞台歌曲和不同版本保留独立。保留 title/album/aliases 中的版本字样，不剥离 Live、翻唱等词。
- 元数据相符仍不等同于已确认同一录音。来源选择页说明证据限制；不删除收藏、曲库或原始结果。

## 展示与播放

搜索原始结果保留所有 UnifiedSong。Compose 行展示合并项，来源选择列出每个原始载体及真实音质信息。用户选择的原歌曲进入已有播放、队列和歌曲菜单入口，不生成播放地址、不切换全局平台。正在播放/待播放状态映射到展示组键。歌手、专辑、歌单操作使用分类 + Provider + 原 ID，防止跨平台碰撞。

最佳匹配仅在非空关键词精确匹配时展示；已知不可播放歌曲不作为最佳单曲。每个增量批次按相关度排序，已有行稳定保留位置。来源优先只在相关度档位内加权，不能压过精确匹配。当前未引入偏好加权及跨平台可播放性探测。

## 验证与范围

S3.2 搜索/原生模型/页面归属专项：16 文件、116 测试通过、0 失败；TypeScript typecheck 通过。随后补跑原生模型与原有推荐回归，具体数量见阶段日志和实施报告。验证覆盖来源 ID 碰撞、版本区别、缺失数据、时长链漂移、目录证据范围、精确排序、增量稳定、来源播放原载体和原生列表状态。全部为单元或模型验证，无真机截图、真实平台播放或帧耗时证据。

高级重复歌曲管理及用户确认的歌单迁移仍未开放。回退 S3.2 实施提交即可恢复搜索逐来源展示，未改变数据库或原歌曲身份。
