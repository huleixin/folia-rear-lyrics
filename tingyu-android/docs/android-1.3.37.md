# 听屿 Android 1.3.37

## 通知栏暂停后进度继续走、无法恢复播放

用户反馈音乐已经暂停，但系统卡片仍显示暂停按钮、进度还在前进。代码中确认存在这样的状态链路缺口：系统命令直接调用 Media3，Media3 的暂停/恢复事件原先只发给 Web 插件；前台服务的缓存、通知按钮和 MediaSession 刷新仍等待 WebView 发布状态。后台 JS 延迟或插件没有监听时，实际输出与系统已发布状态可能脱节。

本版修正该同步路径，并不将代码分析等同于已经在小米通知栏上复现、验证：

1. Media3 的状态、跳转和错误等低频事件直接刷新现有播放服务与 MediaSession；即使没有 Web 监听也执行。暂停状态在主线程事件返回前发布，不再额外排一个可能在 CPU 休眠后才运行的刷新任务。
2. 通知服务收到 Web 状态时，当前歌曲的原生位置与播放状态优先。迟到的“仍在播放”不能让系统暂停时钟继续走，迟到的暂停状态也不能覆盖原生恢复。上一首歌曲的迟到数据继续被拒绝。
3. 自有通知的播放按钮使用稳定的 toggle 指令，按执行时的当前播放意图切换；淡出暂停过程中再次点击可以恢复。系统显式 play/pause 命令仍保持幂等，不将耳机/系统的明确暂停改成切换。
4. 同步保留既有封面和元数据，只在真实播放状态改变时重建按钮通知，不重复启动服务、下载封面、写队列。相同状态和近似时钟去重，显式 seek 不被去重；没有轮询通知栏，时钟/频谱帧不触发此同步。
5. 服务销毁时先撤销发布入口，播放器释放前先撤销其有效源和监听，防止退出中的旧回调读取已释放播放器。

## 保留

- Media3 解码、淡入淡出、音源、后台原生队列和下一首逻辑不变。
- 不增加 CPU/Wi-Fi 常驻锁，不改变音频 offload、安全输出切换或全局帧率。
- 不改 UI、歌词舞台及防闪烁方案。沿用 1.3.36 的背屏相机让屏和 LSP v5；尚未载入 v5 模块的用户覆盖安装后仍需重启手机。
- 兼容通道保留 Web 状态来源；其既有 toggle 处理继续使用。

## 验证

- 162 项 Android JVM 测试通过（本轮新增 12 项），包含原生暂停冻结、恢复重新计时、迟到状态、暂停时跳转、重复事件去重、小幅显式 seek、淡出期间切换和系统显式命令幂等。
- 34 项前端回归测试通过，覆盖 nativeAudioElement、nativePlaybackBridge、nativePlaybackPublishing、mediaSessionSync 和 nativeAudioDeck。
- Android 发布构建、必要的 lintVital、APK v2/v3 签名和版本信息校验通过，versionCode 为 61，沿用原正式证书；不是图形诊断或播放测试构建。
- 未连接手机；没有测量通知延迟或功耗百分比。纯逻辑测试不能代替小米 SystemUI、锁屏与真实 Media3 输出验证。
- 本轮没有重复执行全量 lintRelease；1.3.36 已记录的存量 Lint 问题不在本轮修改范围，不能将 lintVital 通过表述成全量 Lint 通过。

## 复测

播放同一首歌并把听屿留在后台，在通知栏暂停后等待 10–30 秒：音乐应停，进度应冻结，按钮应切为播放。再从通知栏恢复，音乐和进度应从暂停位置继续。重复暂停/恢复，并在锁屏、切歌后、暂停时拖动进度以及快速双击时测试。不要为了这项验证常亮主屏。

若再发生，导出诊断；本版会记录 `native-session-state` 的播放状态和位置，便于与卡片截图及服务心跳对照。
