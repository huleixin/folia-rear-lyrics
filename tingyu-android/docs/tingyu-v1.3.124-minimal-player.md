# 听屿 v1.3.124：极简播放器与舞台交接

基线：最新主分支 `62797e60`（v1.3.123 / 146），保留此前全部提交，未重新克隆。
本版 versionName 1.3.124，versionCode 147。

## 用户可见变化

- 极简歌词右上角进入舞台：真实歌词画面与顶栏向上展开；返回向下收回。
- 临时进入舞台时返回原极简歌词页，保留分页与滚动节点；直接选择舞台模式时保持退出播放页的导航。
- 封面缩小约一成，背后使用轻微倾斜的半透明底片。
- 封面页、歌词页均可从有有效目录身份的歌手名进入现有歌手详情页，返回上下文为播放器。
- 修复首次打开极简页的“更多”菜单缺失样式、文字挤成一列及与顶栏重叠。
- 将用户提供源码的 AuroraBgView 三层随封面取色柔光机制适配为当前背景层，兼顾浅色与深色。

## 已确认的代码问题

1. Android Back 先派发 Escape。播放交互监听器消费后直接调用 `navigateBackFromPlayer`，绕过只在另一路径检查的 detour；现在返回底层入口同样处理临时访问，收回过程中重复返回不会穿透到首页。
2. 旧转场仅保留极简页 400ms，完成后卸载，返回时重新挂载并淡入；现在临时舞台下保留原节点，遮挡时关闭点击、歌词逐帧订阅及背景动画。
3. 极简菜单复用 MobileStageMenu，但样式只由另一个懒加载的舞台页面导入。现将样式移至菜单自身模块，菜单固定在“更多”按钮下方，具备滚动和屏幕宽度限制。
4. 原生 stage 提交仅检查 app-shell 的播放器标记；该标记不能证明懒加载的 MinimalStage 已存在。现在还要求实际极简页面挂载标记，随后沿用 WebView visual-state 回调接管。
5. Android 展开时内部页面、内容和控件分别入场，空白时刻暴露整屏底色。现在 Android 用同一个 WebView 的原生位移，保留原生上一页直至入场结束，取消内部重复入场。
6. 封面只使用 onload，并非真正的 decode 完成。现在等待 decode，且以有界的 16 个 URL 就绪缓存复用最近封面；不常驻额外位图。

用户录屏已证实进入时存在空白底色和内容分段出现。这些代码缺陷已针对性修改，不能仅凭浏览器验证断言小米合成器的闪烁已经完全消除。

## 架构与性能边界

- 播放器、队列、歌词权威时钟、LSP 原生卡片、Shizuku 和 AOD 调度未改。
- 舞台画面、Web 顶栏共用 CSS 方向；原生 Compose 播放栏收到离散方向元数据自行执行位移，不每帧跨桥发送坐标。
- 原生首次展开与 CSS 内部舞台切换分工独立，不复制舞台、不使用截图动画。
- 歌手导航复用现有目录适配器和原有详情页。独立的操作 hook 处理重复点击、晚到响应、换歌或离开页面；不改变原先队列面板里的歌手入口。
- 多歌手分别使用各自身份。没有有效目录信息的文字不显示可点击箭头，不用标题或歌手名伪造平台 ID。
- 柔光使用三层预绘制径向渐变及 transform 动画；无新的 Canvas、Shader、FFT、模糊循环、逐帧 React 更新或播放器查询。
- 暂停、应用隐藏、舞台覆盖或系统减少动态效果时停止背景动画。切换封面才重新计算配色。
- 只参考用户压缩包的背景机制，没有搬入其播放器、歌词时钟、网络服务或签名文件。

## 需要真机确认

1. 强停后立即点击迷你播放条，确认展开期间不出现空底色及内容反复显隐。
2. 极简歌词 → 舞台 → 全面屏返回：向下收回到同一个歌词页；重复快速返回不会直接跳首页。
3. 在设置里直接选择舞台后进入，确认返回正常退出播放器。
4. 两页点击单/多歌手，进入当前音源详情，返回保留原播放位置；快速换歌时旧查询不能误导航。
5. 深色、浅色、暂停/恢复、后台回来、旋转或 Activity 重建后布局正常。
6. 原生播放栏与 Web 歌词舞台位移方向一致，没有原生栏提前出现或延后残留。

本轮无连接真机，不宣称 Android 屏幕帧率、闪烁消除或功耗已有实测证据。
