# 边听边存、歌单缓存与洛雪备用音源

本专项正式集成到 `1.5.46`（versionCode 261），沿用原正式版包名和 Release 签名，可覆盖升级。先前的 `1.5.45-playback-test.3` 为独立测试包。

## 使用入口

1. 安装或更新「听屿」1.5.46。原正式版可直接覆盖升级；独立测试包的数据不会自动迁入正式版。
2. 在设置的存储页面找到「离线音频缓存」，开启「边听边存」。默认关闭；「仅 Wi-Fi 自动缓存」默认开启，「播放歌单时自动缓存整单」默认关闭。
3. 在线歌单中点击「缓存歌单」，在存储页面查看进度、任务详情，重试失败任务或停止整单缓存。未开启缓存时，按钮先打开存储设置。
4. 洛雪音源页面可开启「平台原音源优先」。原平台失败后，仅尝试当前启用的洛雪音源；明确的权限、会员、购买、地区等限制不会因此绕过。
5. 需要多脚本接力时，开启「启用备用脚本」，给其他导入脚本点击「加入备用」。可提前备用顺序；仅导入而未加入备用的脚本不会自动使用。
6. 可选择 1、2、4、8 GB 空间上限，默认 2 GB。清空缓存与任务需要再次确认。

## 已实现行为

- 完整缓存优先读取，再请求音源；完整文件可跨应用重启使用，播放仍有本地读取和解码准备时间。
- 稳定通道的本机音频代理和 Media3 数据源复用正在播放的字节，不在听完之后再额外下载一整首。
- 按平台歌曲身份、请求音质、脚本内容和播放策略区分缓存。策略改变后停止旧任务、清除未完成文件；已完成文件保留，但不会混用到新策略。
- 歌单分页通过 Omni 获取，每页 50 首。歌曲任务和分页位置持久化、去重；只有原生确认入队后才推进位置。
- 原生后台每批最多处理 5 个任务，同一时间只下载一首；系统停止任务或网络条件不满足时取消下载。失败由用户主动重试，不无限循环。
- 原生续播和前端都支持多脚本顺序、跨平台录音匹配、声明音质降级。跨平台检查歌名、全部歌手、版本标记和时长，不能确认时不换歌。
- 播放解析共享约 65 秒尝试预算、最多 12 次 musicUrl 调用；单次请求及脚本初始化最多使用剩余预算中的 15 秒。前端初始化超时会终止对应 Worker 和 HTTP 请求，原生备用 VM 在尝试后释放。
- 缓存的音频字节须连续完整，且容器、音轨时长、首尾样本、DRM 标记通过检查；失败文件不作为完整缓存播放。
- 标称音质和协商档位保留为元数据，`qualityVerified` 始终为 false，不声称完成逐样本解码或鉴定真实 Hi-Res。使用备用录音时不会套用原平台录音的 ReplayGain。
- 缓存解码失败会失效对应缓存，再按现有播放恢复流程尝试音源，避免反复读取同一坏文件。

## 数据与性能边界

音频与元数据在应用私有 `files/audio-offline-v1`，任务在私有 SQLite `audio-cache-jobs.db`。后台任务只保存白名单歌曲元数据与路由标识，不保存解析后的临时 URL、请求头、Cookie 或 Token。实际请求仍使用既有平台凭据和音源配置。

播放文件通过本机随机令牌 URL 或原生私有文件路径读取，整首 Blob/Base64 不跨桥传输。文件写入和格式验证使用专用线程，队列最多 32 个写任务，最多 4 个在途文件，单文件上限 256 MB。空间不足或队列满时放弃缓存，播放继续。后台下载使用 64 KiB 缓冲并节流，连接 8 秒、读取 15 秒、整体请求 180 秒超时。

任务最多保留 10000 首、20 个未完成歌单。设置可见时每 4 秒查询状态，界面隐藏后停轮询。开启功能后会增加磁盘写入、网络下载和少量校验开销；没有真机功耗与播放稳定性测量，不承诺零开销。

## 尚需设备验证

本机没有连接 Android 测试设备。请用两个播放通道分别验证：

1. 开启边听边存，完整播放一首可用音频，确认缓存数量增加；关闭应用，断网重开，从仍可访问的歌曲/播放队列中播放该曲。
2. 整单缓存完成后重启，断网播放、切歌、拖动进度；失败歌曲应明确列为失败，不能计为已缓存。
3. Wi-Fi 切换移动网络、断网恢复、锁屏、后台及杀进程，核对网络限制与任务恢复。
4. 多脚本和跨平台匹配，核对实际曲目没有切换到翻唱、现场、伴奏或其他版本；使用不能提供完整音频的歌曲检查失败处理。
5. 检查深浅色、经典/冰川主题与 Pad 页面，缓存过程中验证暂停、切歌、歌词、背屏和播放稳定性。

## 已知限制

- 不读取或解密 QQ 音乐、网易云等其他应用的加密缓存，不绕过会员或版权限制。仅缓存音源实际可提供且允许保存的完整、未加密音频。
- 完整音频离线可用，不代表未保存的歌单页面、封面、歌词或搜索请求也都能离线加载。
- 歌单尚未发现的分页需要应用 WebView 活跃；后台只下载已经发现并入队的歌曲，回到应用后继续发现后续页。
- 跳播、拖动进度或提前退出会留下字节缺口，不能当成完整缓存。未完成范围不会跨进程断点续传，持久化任务会重新解析/下载。
- 切换音源策略后旧完整缓存仍占空间；恢复同一路由才会匹配，或由容量清理/手动清空删除。
- 超大文件、服务器未知长度、分段流、DRM、时长缺失或格式校验不通过均可能无法缓存；超过后台整体超时的下载也会失败。
- 原生宿主沿用既有预热与同步锁；已开始的预热占用锁、系统调度或不可中断的底层操作可使实际耗时超过尝试预算，预算不是所有线程的硬实时上限。
- 完整字节和首尾样本检查不能保证每一个样本都可解码；实际播放失败后才触发失效与恢复。
