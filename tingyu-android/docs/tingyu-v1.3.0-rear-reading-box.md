# 听屿 Android 1.3.0：背屏歌词阅读区

本轮先解决“所有背屏都乱”的根因，再逐项收紧排版。所有结论来自本地背屏预览台（真实 CSS 尺寸 329×208、393×249、904×572）截图，不是推算。

## 根因一：歌词从未被放进镜头右侧

`resolveRearReadingSurface` 的 37% / 60% 只影响字号与少数画布的绘制偏移，DOM 歌词仍然铺满整块背屏，所以会压到摄像头；翻译字幕用的是手机的底距（约 112px），在 208px 高的背屏上正好落在画面中间，与主歌词叠加。

现在 `VisualizerShell` 增加一个阅读区容器：左侧避开镜头、底部避开播放控件，歌词与字幕都在其中布局；容器内坐标从 0 开始。

## 根因二：画布逻辑高度被强制拉高

花火/凝彩/商籁/绘光的 Pixi 画布有 320×240 的最小下限。背屏高 128px 时画布仍按 240 建，CSS 却只有 128，纵向被压成 56%，这就是“字被压扁”。现在该下限只在正面舞台生效，背屏按真实尺寸建画布；实测花火位图 395×256 对应 CSS 197×128，严格等比。

## 根因三：桌面排版直接塞进小框

- 默认、华彩、云阶、静态改用按实际文字测量的字号（pretext 换行，最多两行，为字幕留出底部空间）。
- 云阶在背屏改为单列，按宽度决定行数，去掉横向错位。
- 气泡在背屏只显示当前一条，隐藏头像与时间戳，避免两条消息把内容顶出框外。
- 环形在背屏缩小字号与半径。
- 主歌词容器去掉 `70vh`（在背屏上等于整块面板高度）。

翻译/罗马音字幕改为阅读区底部的独立带，字号按高度限制在 11–14px。

## 仍是已知不足

莫奈、商籁、钟摆、倾斜、绘光等样式虽然已经回到阅读区、不再压镜头，但各自的海报式排版在小尺寸下仍偏挤或偏小。这一版先把“不越界、不被拉伸、不重叠控件”做稳，这些样式的内部构图需要继续逐个调整。
