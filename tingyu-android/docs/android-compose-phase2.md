# Android Compose 第二轮迁移

本轮改为原生界面固定持有显示权，替代第一轮的网页先显示、等原生绘制确认后接管。版本 `1.3.20-beta.7`，versionCode `40`。

Android 标准构建现默认启用原生 shell；`npm run build:capacitor` 同步启用对应前端契约并关闭旧玻璃实验。测试用浏览器构建仍保持网页显示权。第一轮文档中的默认关闭、失败回退及绘制确认流程仅描述旧构建，不适用于本轮 APK。

## 启动与页面

- `MainActivity.onCreate` 在 Activity 第一帧前挂载 Compose shell。底栏、小播放器、推荐页框架及海报资源随 APK 打包。
- 原生读取上一份推荐、资料库、设置和播放组件的展示快照。首次安装显示同一套原生界面内的加载状态；网络内容及播放引擎仍异步初始化。
- Android 中不挂载已迁移页面的旧网页内容，不因探测延迟、通信失败或退出动画恢复旧控件。普通浏览器始终使用网页界面。
- 原生更新回复只表示数据已接收，不作为更换渲染器的条件。桥接单次失败保留原生 shell，不销毁整个界面。
- 推荐、资料库、歌单、歌手、搜索和设置首页使用 Compose。账号、导入、歌曲菜单及高级设置暂保留已有弹层，通过同一 WebView 叠加，不重复创建播放器或网络业务。
- 进入舞台时原生端立即隐藏首页栏；舞台右上角的小菜单保留原生播放控件。歌单保留原来的小播放器可见性。

## 状态与开销

播放、音源、洛雪、搜索、资料库与设置仍使用现有 store/core。新增接口只传展示信息和离散操作，不传账号凭据、播放地址或完整音源对象。

列表由 LazyColumn 滚动，每次传 100 行，原生保留有界的行缓存；只有跨窗口才请求内存切片。返回缓存行的操作根据当前曲目身份校验。页面滚动状态最多保留 12 份。页面身份与筛选列表身份分离，输入文字不重建输入框。

本地 blob 封面转换为小缩略图，最多四项并行、共享有界缓存；不逐帧截图。原生绘制玻璃继续共用单一背景采样。Android 12 以下使用轻量原生材质。

## 验证边界

本机验证覆盖类型检查、Android JVM 测试、原生编译，以及浏览器模拟桥接下的延迟启动、搜索分页、过期动作、弹层、舞台切换和窗口尺寸变化。浏览器模拟不能证明 Android 像素效果、设备功耗或厂商系统的冷启动时长；本轮不连接用户手机。

后续 Media3 播放链迁移与复杂歌词舞台原生重写不包含在本轮。不能将 Compose 迁移本身当成功耗下降的测量结论。
