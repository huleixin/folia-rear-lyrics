# 听屿 Android 1.3.24 播放紧急修复

1.3.23 将普通播放默认切换到新原生通道，同时不给浏览器媒体元素设置音频地址。该通道即使 capability probe 返回可用，后续初始化/命令/起播仍可能失败或无响应；原实现缺少可靠回退，因而可以影响所有歌曲。用户报告所有歌曲无法播放。

本机已复现这一失败模式：让原生通道报告可用但不响应命令，1.3.23 无法把 HTTP 测试音频交给浏览器播放器，起播检查超时。尚未获得实体手机日志，因此不把“设备上原生起播失败的具体原因”冒充已查明。

## 修复

- 从生产 App 默认路径撤下 useNativeAudioDeck，恢复原有双 deck 音频地址与媒体事件驱动的播放链路。
- 原生 TingyuPlayback 能力报告改为不可用，并拒绝启动命令。即使旧缓存界面尝试原生接管，也会回到原播放通道。
- 原生迁移代码暂时保留但不启用，等待 Android 运行时验证后再推进。
- 保留 1.3.23 的洛雪歌单支持、界面性能改动、Liquid Glass、歌词样式与背屏业务。本次不重新调整布局或动画。

## 验证

- 修复前：原生通道报告可用但无响应时，真实 HTTP 音频起播检查失败。
- 修复后：在同一故障注入条件下，真实 Chrome 音频解码、播放、暂停、恢复、歌词舞台拖动与暂停均通过；生产 App 不再申请新原生播放引擎，共 8 项浏览器检查通过。
- 播放、恢复、取流、洛雪歌单及通知桥接等 450 项测试通过；TypeScript 检查通过；安卓 JVM 测试与发行构建通过。
- 发行 Web 产物不含 TingyuPlayback 调用，沿用既有听屿证书签名；versionName 1.3.24，versionCode 48。

未连接实体手机。以上浏览器实播验证不是 Android 真机验证，安装后仍需确认用户设备上的歌曲与音源恢复。建议直接覆盖安装修复版，无须先卸载。
