# 1.3.115 AOD 歌词时间轴自适应调度（待真机验证）

## 审计结论

1.3.114 的 500ms 位于 visualizerFrameChannel：同时限制歌词时钟计算、Canvas 回调及 Pixi 手动更新，不是单纯的数据检查。播放快照仍按 1000ms 校准，原生状态语义变化触发立即读取。实际屏幕呈现由 WebView/系统 DOZE 合成决定，500ms 不等同实际 2 FPS。

Folia 参考 CardRenderPolicy.resolve 的 500/1000ms 是宿主更新策略；EngineView 向同一前端传递 fps 和时钟，不能直接当成屏幕呈现帧率。本轮保留同舞台，仅修改 AOD 的内存时间轴规划与调度。

## 实现

- 每次歌词版本变化预构建时间轴关键点，运行时二分查询，不逐帧遍历全曲或重读缓存。
- 有精确字词时间时演唱区间目标 10 FPS；句首 600ms、句尾 400ms 的过渡区间最多 12 FPS。重叠和声共用同一有界预算。没有字词时间时不虚构字词时间，只更新句边界。
- 歌词间隙不连续刷新，单次定时等待下一关键点；暂停后返回无连续绘制需求。Seek/播放状态/倍速显著变化及新歌词触发一次即时刷新，然后按新锚点重新规划。
- 使用已验证播放快照建立 performance.now 单调时间锚点，帧间插值只读 ref。NORMAL 仍走原逻辑；AOD 不改变用户样式或数据源。沿用既有歌曲/会话/epoch 验证与防串歌机制。
- 原始快照读取仍为 1 Hz 校准，不提高至绘制频率。校准误差小于 150ms 且状态/倍速无变化时不触发静止画面重绘。音频响应与动态背景仍停用。
- 同一个需求函数传给外层背景文档，内外不建立平行时钟。AOD 退出、隐藏、歌词版本替换会取消旧定时；不补播过期动画。
- 连续三次明显晚于目标时间运行时降级为至少 500ms，等待后续状态变化重评估；不请求亮屏，不补积压帧。

## 诊断

沿用 aod-stage：记录目标 FPS、时钟计算次数、绘制回调请求次数、延迟计数、回调墙钟耗时、idle/cancelled、样式与模式，定期汇总或状态改变记录。presentedFps 固定为 unmeasured；callbackWorkMs 是同步回调墙钟时间，不是进程 CPU 或 GPU 功耗。原生 render-mode 仍记录显示电源与身份。日志不含歌词正文。

## 验证

TypeScript、45 项相关前端测试通过；覆盖关键点、长短句/快速词、重叠和声、倍速、Seek/暂停、50 次歌词代次规划、静止 60 秒不重绘、隐藏取消、恢复及原 NORMAL 帧率。912 Android JVM 通过、仪器测试包编译通过。

浏览器 Playwright NORMAL→AOD→Seek→NORMAL：同舞台节点保留、iframe AOD 正常、异常 0。没有连接真实小米设备，不宣称实际屏幕达到 10/12 FPS、不宣称已测得功耗或长期稳定性收益。

手机验收：原签名覆盖安装后重启模块；对长句/快速歌词/间奏/暂停检查逐字及滚动，反复 Seek、切歌、倍速、收起再展开、相机、AOD 开关，检查退出无积压动画；锁屏连续播放 1–2 小时并比较同条件功耗、Perfetto/FrameTimeline。系统可能将 WebView 定时器或合成进一步限速，以实际呈现为准。

本轮未修改原生卡片绑定、LSP 单一显示、Shizuku、播放核心或舞台视觉。回滚本轮提交后提高 code 原签名构建，不卸载清数据。
