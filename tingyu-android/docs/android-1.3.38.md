# 听屿 Android 1.3.38

## 歌单歌曲规格标签

歌曲的歌手名旁增加低饱和薄荷色小标签，可显示 HQ、无损、Hi-Res、杜比、DTS。每行最多两个标签；原生窄屏或大字体时收敛为一个，优先保留歌曲、歌手、时长和菜单的空间。既有行高、播放高亮、定位当前歌曲、分页、返回和播放控制不变。

标签表达平台曲目目录中明确提供的规格，不表示账号已获得播放权限，也不表示当前实际播放流的品质。特别是启用洛雪来源后，QQ 歌单标签仍属于 QQ 曲目；实际取流音质继续由原播放器小控件显示。没有可靠数据则隐藏标签，不使用 VIP 标记、用户音质设置、URL 扩展名、脚本支持的音质列表或未知位标记猜测。

## 数据与缓存

- QQ：核对公开 `music.pf_song_detail_svr.get_song_detail_yqq` 的真实 file 字段，保留桥接层原先丢弃的必要数字。只解释命名明确的 `size_320mp3`、`size_flac`、`size_ape`、`size_hires`、`size_dolby`、`size_dts`；不解释未知 `size_new` 位。DTS 不推断为 DTS:X，杜比也不推断为 Atmos。
- 网易：从已经取得的曲目对象 `hr`、`sq`、`h/hMusic` 的有效规格记录提取，规格必须有正数大小；HQ 另检查高品质码率。仅有 maxbr、会员权限或空规格记录不生成标签。本机公开接口探测超时，该部分验证使用协议形状的单元测试，未完成当前线上响应验收。
- 酷狗：复用曲目已经返回的 HQ/SQ 备用文件哈希，仅接受合法非占位哈希；不新增音频取流。其他平台、本地与 Navidrome 没有这批已验证字段时保持不标注，不能承诺所有曲目都有标签。
- 统一使用可缓存的 `catalogAudioSpecs` 枚举，规范化、缓存回读和原生页面协议均保留；列表只消费规范化数据，不直接请求平台接口。
- 不逐首查详情、不逐首取流、不扫描音频、不触发解码；只随原歌单请求处理响应并复用现有缓存。旧缓存没有这些信息时暂不显示，可使用歌单原有刷新动作重新加载；不为新增标签清空整库或强制重拉全部歌曲。

## 原生与性能

Compose 歌单及移动端 Web 列表均接入。原生协议最多携带两个短标签及无障碍说明；旧页面缓存和无标签曲目保持兼容，分页缓存可更新同一条目的标签。原生静态文字和细边框不创建动画、模糊或整屏 GPU 图层；Web 复用父行翻译函数，不增加逐行数据订阅。播放引擎、频谱、歌词舞台和背屏没有改动，保留 1.3.37 通知栏同步修复。
