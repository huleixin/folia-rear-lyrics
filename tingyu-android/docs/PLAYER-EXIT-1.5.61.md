# 播放器转场修正记录 · 1.5.61

## 录屏与源码结论

对照用户提供的 `video(21).mp4`、`video(22).mp4` 与 1.5.60 源码：录屏可见封面、面板边缘和控件的多个历史位置叠在一起。经典播放器还存在明确的动画回归：初始化后的交互进度把 Salt 原有七条位置/尺寸曲线统一成同一个值，并且整个经典内容根节点又套了一层缩放平移。它改变了经典原有分层节奏。

拖影的完整设备调用链尚未取得。当前原生宿主底层透明，转场主要更新子图层，因此本版补充转场期间的完整不透明底层与绘制阶段状态订阅，以覆盖旧位置。该修正需要在出现问题的手机上验证，不能仅凭单测断言 GPU 拖影已消失。

**更正 1.5.60 说明：**“Offscreen 全屏缓冲必然保留上一帧”没有充分证据；离屏合成本身不等于缓存历史帧。本版不沿用这一结论，也不宣称此前“移除残影”已经得到真机证实。

## 改动

- 经典点击进出重新使用原 Salt 七条独立曲线、980 ms 进场和 500 ms 退场时序，以及原有标题、控件、歌词和装饰渐显节奏。移除经典整页的额外缩放平移，未改歌词渲染器及其逐字效果。
- 慢拖仍可抓住正在运动的页面：以抓住时的真实面板位置与独立动画状态为起点，保留反向、取消和回弹。点击退场从当前实际状态收起。
- 修正面板已经到位但装饰仍未完成时的中断，以及快速重开残留拖动状态；旧动画取消后不能提交页面退出。
- 两套原生极简播放器转场时共用完整底层重绘。动画状态在绘制阶段读取，避免为底层每帧重绘而主动重组整个页面。歌词舞台覆盖时不启用该底层。
- 封面继续由现有共享图层绘制，保留封面走到迷你播放器终点的连续性；保留此前的安全区、封面尺寸与按钮布局修正。

## 文件

新增 `chrome/ClassicPlayerFrame.kt`、`chrome/PlayerFrameUnderlay.kt`，修改 `minimal/PlayerPanelState.kt`、`chrome/MinimalPlayerMorph.kt`、`chrome/ComposeChromeHost.kt`、`minimal/ui/MinimalPlayerScreen.kt`。`chrome/MinimalCoverOverlay.kt`、`minimal/immersive/ImmersivePlayerHost.kt` 仅修正未经证实的合成解释注释。路径均以 `android/app/src/main/java/io/github/huleixin/tingyu/` 为基准。

新增经典曲线/中断测试、底层脏缓冲覆盖测试，以及 `android/app/src/androidTest/java/io/github/huleixin/tingyu/chrome/PlayerFrameInvalidationTest.kt` 真机绘制订阅测试。同步调整封面终点测试，封面不在到达迷你栏前消失。

## 验证边界

- Android UI 归属检查：18 项通过。
- 13 类、56 项相关 JVM/Robolectric 回归通过：经典独立曲线、慢拖反向、取消回弹、快速中断、两套播放器手势、封面、歌词视口、底部控件及主题。
- Native Graphics 脏缓冲覆盖测试通过：连续复用同一张位图，不透明底层覆盖前一位置的半透明矩形。此结果仅验证绘制原语，不代表设备合成验收。
- 屏幕重绘测试最初在 Robolectric 中未触发真实屏幕绘制，截图强制重绘又超时。转为 Android 真机测试后编译通过；当前没有连接设备，未执行，不将其计为通过。
- 真机慢拖/快拖/反向/快速进出、实际拖影、帧耗时、掉帧率、长期播放及音频连续性：待验证。
