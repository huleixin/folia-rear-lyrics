# 听屿 Android 1.3.15：普通播放功耗优化

版本 1.3.15，Android versionCode 28。针对「正在播放、停在歌单页、背屏关闭仍发热」做音频图与后台刷新优化。

## 实现

- 自动混音关闭且没有过渡正在收尾时，双音轨直接经过 ReplayGain、trim 和 fade；不创建/连接混音的三段滤波、echo 延迟/反馈、测量用 FFT 和加权滤波。启用时再建立；正在进行的交接先完成，再移除支路。关闭时丢弃旧延迟缓冲，防止以后重启混音放出旧回声。
- EQ 关闭或十段均为 0 时直接旁路，不在音频通路中保留十段滤波。首次使用非零 EQ 才分配；关闭先让 15ms 增益平滑收敛，150ms 后切回直通。快速重开会取消旁路定时器。
- 音效原本已经可以旁路；本轮进一步延迟分配整组节点、曲线及发生器，关闭/全中性时不创建，关闭后释放。音效、音量、播放淡入淡出的顺序不变。
- Android 仅在播放且可见主舞台或醒着的背屏需要时连接可视化分析器；普通资料库听歌、背屏关闭时直达输出。页面可见性、暂停/继续、主舞台及背屏开关都会更新连接。
- 原帧率诊断在应用启动后按原生刷新率持续采样，绕过舞台限帧。Android 改为被动记录长任务/长动画帧，生成诊断报告时按需采样约 1.2 秒并停止；并发报告共用窗口。桌面保持原有连续采样。入口先初始化 Capacitor，再判断平台，避免过早把 Android 判为 web。

未修改歌词样式、摄像头安全区、音质选择、在线请求/缓存策略、后台播放唤醒策略。保留 Web Audio，不是迁移到 Android Media3。没有通过强制降音质或关闭原有功能省电。

## 证据与边界

真实 Chrome 音频引擎将同一合成音源送入发布版 1.3.14 的音频模块与本轮模块，关闭混音/EQ/音效/舞台分析时：

| 指标 | 1.3.14 | 1.3.15 |
| --- | --- | --- |
| 分配节点（含两路源及 destination） | 62 | 14 |
| 实际连接的节点（相同计数口径） | 44 | 13 |
| 连接的 BiquadFilter / Delay / Analyser | 20 / 2 / 3 | 0 / 0 / 0 |

32/44.1/48/96kHz、多档音量、静音、EQ/音效/混音/分析开关的 72 组输出检查通过；直通误差低于 1e-5。使用真实 HTMLAudioElement、AudioContext 及播放 hooks 的 25 项开关/暂停/继续检查通过，始终只有一个 AudioContext。

实际 App 的 Android 平台标记浏览器检查：三次进入/离开主舞台，资料库遮挡状态为 true，主可视化组件子节点数为 0；用合成音源在真实迷你播放器点播放，音乐持续、背屏关闭。玻璃原样与暂时去除 backdrop-filter 的两次各 3 秒观察中，持续 requestAnimationFrame 请求均为 0。诊断按需采样后取得 121 帧并停止，之后 3 秒新增 RAF 仍为 0。另进入真实歌单详情页，持续播放且主画布为 0，3 秒观察到 1 次零星 RAF 请求，没有持续循环。这里只说明没有持续 JS 刷新循环，不能推导 GPU 合成没有成本；玻璃效果保留。

使用 Playwright + 已安装 Chrome（Browser plugin 不可用），不是安卓实机。没有连接安卓设备，没有量测功率、电池下降、温度、蜂窝网络或真实在线解码的功耗分摊。节点减少不等于同样比例的整机耗电下降；省电/降温幅度需在相同歌曲、音质、网络、亮度和播放时长下实机对比。舞台渲染和网络仍有独立成本，本轮不宣称全部解决。
