# 听屿 Android 1.3.36

本轮修改背屏与相机、电源策略的协调，不改主屏 UI、歌词视觉、舞台进出、防闪烁方案或 Media3 播放核心。

## 相机冲突

- 代码确认：原恢复器检测到背屏被其他任务盖住后会重新拉起歌词，没有相机让屏条件。该逻辑可能与系统相机接管背屏竞争；相机是真正崩溃还是任务被挤走，仍需要现场日志。
- 背屏启用时使用 CameraManager 的事件回调监测相机可用性，不新增相机权限、不开相机、不采集画面。
- 初始化回调期间阻止启动，有相机不可用时隐藏并交还独立歌词任务、释放 LSP 租约；停止拉起、迁移和唤醒，取消旧启动回调。相机切换镜头时仍保持让屏；全部空闲且稳定 900 毫秒后按原启用意图恢复。
- 关闭背屏时注销监听，旧回调不能恢复；相机快速退出时也要等原窗口及电源清理完成。恢复失败保留诊断和重试，不以抢回前台作为兜底。

## LSP 与系统背屏息屏

- 原实现已经包含电源策略副本、窗口防休眠、20 秒续期/60 秒超时，不能把它描述成此前完全没有保亮。
- 对照 [AOSP Android 16 DisplayManagerService](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android16-release/services/core/java/com/android/server/display/DisplayManagerService.java)，`requestDisplayPower` 可直接调用物理显示设备，绕过 `DisplayPowerController.requestPowerState`。旧钩子没有覆盖这条路径。
- 增加此方法的可选适配，只在已验证背屏的有效租约内暂代直接 OFF 请求。保留最新原请求，在释放、到期、进程退出和相机让屏后恢复；较新的重置请求使旧回放失效。
- 主屏、非租约屏、DOZE、正常重置、系统设置不变。相同续期不重复操作已应用的电源状态，没有增加常驻 GPU 层或全局唤醒锁。
- 协议升至 v5，覆盖安装后需要重启手机才能加载新模块。旧模块明确提示重启，不静默切换模式。

## 验证与边界

- JVM 测试覆盖已有背屏策略、租约、窗口交还及新相机初始化、同时占用、切镜头、防止旧回调恢复、原始电源请求恢复、旧请求失效、超时和更新租约。
- Android 构建与测试只验证代码和纯逻辑；未连接手机，不能证明小米系统开关确实调用新增钩子，不能据此声称相机闪退和锁屏息屏已在实机消除。
- 无功耗实测数据。本轮没有改 Media3、音源或绘制帧率，也没有添加帧循环/持续相机轮询；新增成本来自相机状态事件及租约边界上的电源协调。

实际执行结果：150 项 Android JVM 测试通过（新增 13 项），`assembleRelease`、发布必要的 `lintVitalRelease` 与 APK v2/v3 签名校验通过；包名和发布签名保持一致，versionCode 为 60。普通构建，图形诊断和播放测试开关均关闭，原生播放保持开启。

全量 `lintRelease` 未通过，报告 45 个错误：44 个对应代码行在 1.3.35 已存在，另 1 个为未跟踪的本地 SDK 路径格式提示；本轮新增文件没有 Lint 错误。已记录逐项原代码行对照，未关闭检查、添加忽略基线或把全量 Lint 描述为通过。本轮不扩展修改既有 Media3 API 注解、旧系统 API 兼容和其他页面返回等存量问题。

## 安装后复测

1. 覆盖安装，LSP 用户重启手机并确认桥协议 v5。
2. Shizuku 模式播放并开启背屏歌词，打开相机、切前后摄/镜头、退出相机，检查相机是否正常、音乐是否持续、背屏是否恢复。
3. 相机已打开时启用背屏歌词，确认不抢相机；退出后应自动出现。相机期间关闭背屏，退出相机不应重开歌词。
4. LSP 模式保持系统「背屏息屏」开启，播放时锁屏观察至少两分钟；检查暂停 30 秒交还、恢复播放、遮盖息屏和关闭背屏。
5. 若仍异常，导出原有诊断日志；重点查看 `cameraBlocked`、`cameraYielding`、`rearDirectPowerHook`、`directHookError`、`directLast`、`leaseRemainingMs`、`rear-power-changed` 和窗口事件。不要仅凭桥已连接就判定适配成功。
