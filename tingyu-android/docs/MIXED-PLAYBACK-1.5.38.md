# 跨平台混播与备用音源 1.5.38

基线 53873195（1.5.37）；分支 feat/tablet-adaptive；versionCode 253。未合并 main。

## 用户可见变化

- 切换浏览平台时保留当前播放、队列、歌词、封面和 FM 状态。在 QQ、网易云等平台找到歌曲后，通过现有“加入队列”动作组成混合队列；点击播放整张歌单仍沿用原有替换队列语义。
- 队列身份继续使用 providerId + mediaId。不同平台即使歌曲 ID 相同也不会互相覆盖。FM 补曲使用当前 FM 歌曲所属平台，不随浏览平台切换。
- 平台原版取流失败、没有完整可播地址或实际媒体地址播放失败时，自动搜索其他平台的同一录音。只替换音频来源，保留原歌曲的队列、收藏、歌词与封面身份。
- 匹配要求完整歌名和歌手集合规范化后相同、双方时长已知，时长差不超过 5 秒且不超过原曲的 3%。Live、伴奏、Remix 等版本文字参与比较；仅有同名不足以替换。
- 网易云原生取流识别对象及数组形式的试听标志。先继续查询低档完整音频；只有试听片段时报告失败，进入备用流程。

## 范围与边界

- 前台跨平台编排位于 Omni 服务层，在已配置且支持搜索/播放的 QQ、网易云、酷狗、波点、汽水中寻找备用，排除原平台与冷却中的候选平台。
- Android 在 WebView 不工作时，可独立搜索 QQ、网易云目录并通过现有原生解析器取流；原歌曲可来自上述五个平台。后台候选平台须具备可用凭据或后端。后台暂未增加酷狗、波点、汽水目录搜索。
- 用户选定洛雪脚本时继续使用脚本已有的匹配与自动切源策略，不因脚本失败而改走平台原版。
- 已被目录标记下架且禁止入队的条目保留现有拦截；本次处理进入播放流程后的取流与媒体失败。不会把网络、权限或会员错误写成“下架”。
- 无匹配或其他平台也不能完整播放时，沿用原失败/重试/跳过规则。需要对应平台实际提供完整可播音频。
- 搜索与候选取流分别最多等待 5 秒、6 秒，单次备用流程总预算 20 秒；每平台最多解析 2 个候选、总计最多 4 次。前台排除已失败文件（忽略签名参数），原生每个播放会话与歌曲组合最多启动一轮媒体失败备用。
- 异步返回经过歌曲、播放代次和来源校验；过期结果不接管新播放。原生原位替换媒体条目，保留进度并尊重暂停状态。
- 备用字节不缓存到原平台歌曲键；丢失或淘汰的在线地址绑定也不会推测归属。备用音频使用自身 ReplayGain，缺失时采用中性值，避免沿用另一份母带的增益。

## 实现位置

- 混播入口与 FM：createLibraryAccountPort.ts、usePlaybackQueueController.ts、平台切换提示文案。
- 前台解析与恢复：onlineMusic/playbackFallback.ts、omni.ts、audioSourceBinding.ts、onlinePlayback.ts、prefetchService.ts、createOnlineRecoveryController.ts。
- Android：nativePlaylistSync.ts、BackupCatalog.java、OriginalPlaybackFallback.java、ResolverRegistry.java、SourceResolution.java、NeteaseResolver.java、NativeAudioEngine.java。
- 测试隔离：酷狗解析器支持注入 HTTP 客户端，旧身份提取测试改用拦截器模拟网络；续播测试按当前用例前后的诊断计数比较，不依赖执行顺序。

- 前端回归：80 文件、1,261 项通过，覆盖在线平台、播放恢复、队列、缓存、预取、原生队列同步；最终缓存边界调整后相关 15 项复测通过。
- 原生播放/解析器回归：64 文件、486 项通过，零失败、零跳过。覆盖混合队列续播、主取流失败进入备用、严格匹配、目录解析、试听识别、重试与异步过期保护。
- TypeScript 类型检查、主题生成检查通过。
- 原生单测使用 tingyuAllowStaleWebAssets=true，仅允许测试代码在网页资产同步前编译；交付构建重新生成网页并执行 Capacitor 同步，不使用该豁免。
- APK 构建、签名与 SHA-256 记录随交付目录 summary.json 提供。

未连接真实手机或 Pad、未使用用户真实平台账号进行连续播放。实际 CDN 可用性、锁屏/后台自动切源、音频听感、进度与歌词对齐仍需设备验证。本次不调整 UI 布局、不替换 Media3 或 Compose 歌词引擎。
