# 听屿 Android 1.3.16：双屏舞台按需运行与刷新修复

版本 1.3.16 / Android versionCode 29。保留既有音频优化、歌词样式、摄像头安全区和全屏动画区域。

## 修复与运行方式

- Android 主屏舞台同时依据页面可见性和 MainActivity 的停止/恢复信号运行。主屏隐藏时卸载主舞台及舞台装饰动画，保留音乐播放、原生媒体控制和背屏数据发布；未暂停整个 WebView，也没有调用全局 pauseTimers。
- 背屏使用独立入口、独立画布和本地时钟。背屏休眠/页面不可见时卸载其背景与歌词渲染、停止接收轮询；主屏的音乐和舞台不被连带暂停。背屏关闭时不发布歌词快照，休眠时也不继续发送音频包。恢复时读取当前媒体时间，没有补播积压动画。
- 两屏共用现有播放音频图及一次频谱分析；主屏可见时频谱采样最多约 30Hz，只有背屏需要时约 10Hz。两屏都不用时移除可视化分析，保留普通播放路径。Android 暂停时停止逐帧播放数据采样，保留低频进度更新。
- 修复 Windows 构建的调度器重复实例：构建插件曾以反斜杠绝对路径解析虚拟运行时，而普通 import 使用正斜杠路径，导致图形驱动引用另一份未初始化的队列，退回原生 RAF。现在统一模块 ID；构建强制检查恰好一个实例，输出 visualizer-frame-runtime.json。
- 前景歌词/镜头和独立背景采用不同队列。Android 未手动设置时，前景目标 60FPS、独立背景最多 30FPS；保留 30/60/90/120/不限制选项，不限制时两种队列均解除上限。原有帧率选择通过配置传到不同来源的背屏，不再依赖背屏自己保存的设置。
- 帧调度采用相位余量，避免 90Hz 屏幕上的 60FPS 目标被整帧取整压到约 45FPS。主屏与背屏的歌词时钟随前景队列推进；UI 原生 RAF 不受全局替换。
- 暂停后背屏歌词时钟、隐藏控件进度不再持续 RAF；暂停拖动进度仍即时更新歌词和进度。重复的静止时钟/音频包不会反复复制到 iframe、分配频谱数组或通知界面。暂停轮询由 100ms 改为 250ms，播放时维持 100ms 并在背屏本地推算连续时间。
- 默认 Latent 背景原来暂停时保留 12% 动画速度，仍会整屏绘制。现在速度归零停止 GPU 循环，保留最后画面，恢复时继续。莫奈背景的漂移暂停/恢复同一条合成动画，不重建轨迹；回环轴线在暂停后的光晕过渡结束后停止空转。
- 绘光场景和片尾复用共享辉光滤镜，替代缺少极小区域防护的旧副本。原版副本在无法下采样时会读空纹理并中断当帧，实际组合测试复现了异常；共享实现保留原辉光参数，并对极小区域原样输出。

| 显示需求 | 主屏舞台 | 背屏舞台 | 音频分析 |
| --- | --- | --- | --- |
| 仅主屏 | 运行 | 停止 | 一次分析，按需采样 |
| 仅背屏 | 停止 | 运行 | 一次分析，较低频率采样 |
| 双屏 | 分别绘制 | 分别绘制 | 共享同一分析结果 |
| 都不显示 | 停止 | 停止 | 无舞台需求时旁路 |

两种尺寸/摄像头约束仍需要分别绘图；不是把一张主屏画面投到背屏。没有强制降字号、裁掉左侧动画、改变逻辑画布尺寸或降低音质。独立背景的 30FPS 预算不代表合并在 Pixi 场景内部的所有光效都被单独拆开；重样式的完整 GPU 成本仍存在。60FPS 前景本身比实际 30FPS 绘制更费计算，收益来自停止不可见侧、修复无效限帧及消除空转；不能保证每个样式、每台手机都同时更冷且更快。

## 验证

- TypeScript 检查通过；30 个相关测试文件、203 项测试通过。覆盖调度器实例、60/90/120Hz 时间线、前景/背景预算、取消与切换、背屏休眠、快照去重、暂停跳转、莫奈动画暂停恢复、辉光小区域防护、音频图与既有摄像头布局。
- 使用额外 QA HTML 入口构建实际 App 及真实 /rear-lyrics.html 双文档宿主，启用与 APK 相同的 Capacitor 构建插件和驱动转换。QA 入口不在正式构建输入中。
- Playwright + 安装的 Chrome、软件 WebGL（Browser plugin 不可用）。浏览器模拟两块屏幕都可见，并通过同一个原生活动事件切换主屏；原生后端使用模拟接口，实际 HTMLAudioElement/AudioContext 播放合成音源。
- 15 项组合检查通过：主屏单独、双屏、背屏单独、双方休眠、恢复、帧率配置同步、花火/绘光/凝彩/镜台/回环切换、暂停、暂停跳转及继续播放；页面异常为 0。测试字体及背景不是实机照片。
- 仅背屏显示时主屏组件子节点为 0、绘制调用为 0，音乐继续；双方休眠时两文档画布卸载、绘制及频谱采样均为 0；恢复后继续按实时音频更新。暂停时测试用的 Latent 两层背景绘制为 0；暂停跳转后进度显示 00:04。
- 单调度器修复后，轻量场景的两层背景合计约 60 次绘制/秒（约 30 次/层），不再退回原生高刷。详见 JSON 的实际时间窗口；绘制次数不是手机耗电数值，也不是重滤镜场景的 FPS。
- 背屏测试画布 CSS 保持 347×212 全屏。正式产物强制检查调度模块实例数为 1，确认没有包含 QA 入口及 __stagePowerQa。
- Capacitor 生产构建、Android release 构建、34 项原生测试通过。沿用听屿签名，包名 io.github.huleixin.tingyu，可覆盖安装。

未连接安卓实机，未测量整机功率、温度、电池下降或热降频；浏览器测试不能证明某台手机稳定 60FPS。请在相同音质、亮度、网络和样式下对比三种显示组合。更看重续航时可手动选 30FPS。

## 复现与附件

源码包含 dev/dualStagePowerEntry.ts、dev/dualStagePower.html 及相关测试。预览包包含构建脚本 build-qa.mjs、check-stage-power-1.3.16.mjs、JSON、截图、构建/签名/测试日志。将源码中的 tingyu-android 与脚本放在同级，安装依赖后，从应用目录运行 node ../tingyu-layout-1.3.16/build-qa.mjs，再从同级目录运行 node check-stage-power-1.3.16.mjs。QA 站点为独立输出目录，不进入 APK。

stage-browser-before-scheduler-fix.json 来自本轮中间候选构建，供审查调度修复前的绘制行为；它不是 1.3.15 实机耗电基线。正式验收数据为 stage-browser-check.json。
