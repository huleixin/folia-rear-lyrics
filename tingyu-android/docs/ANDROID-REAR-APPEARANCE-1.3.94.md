# 听屿 1.3.94：背屏舞台外观设置精修

## 范围与原因

- 原配置来源使用双选按钮，跟随模式直接移除了后续设置。改成现有样式的独立配置开关；相关设置始终显示，关闭时由 HTML fieldset 真正禁用，原生文档也采集到 disabled，不只改变透明度。
- 浅色外观、静态模式原来只有状态文字。改为同一设置开关；帧率设置与图形设置共享 SettingsFrameRateSlider 和现有四档值。
- 备份恢复原来是裸露的 details。新增标准二级入口及返回映射，保留文件导入、粘贴 JSON 和导出。
- 舞台和主题编辑器原来将 fixed 弹窗嵌在另一设置页面中。393×852 浏览器基线测得主题面板 top=-92.875、height=1037.75、滚动区域数为 0。现在使用页面呈现模式，统一外层标题与真实安全区，内部独立滚动；原正面弹窗呈现默认保留。
- 普通编辑控件使用 App 明暗外观，取色预览仍使用被编辑的颜色，避免编辑出低对比度舞台配色时把操作界面一起变得不可读。

## 主题入口响应

`rearAppearanceModules.ts` 复用现有可取消空闲队列，仅在外观页打开时准备模块；同一 Promise 去重。已加载组件可同步取得，不再经首次 React.lazy/Suspense 回退路径。没有把编辑器加入冷启动入口，也没有新增轮询。

同一台 Windows 开发机、Chromium、Vite、393×852、模块已准备好，通过页面内部事件至 DOM 挂载的单次对照：

| 阶段 | 修改前 | 修改后 |
|---|---:|---:|
| 主题编辑器挂载 | 305.6 ms | 27.1 ms |

这是开发浏览器样本，不是 Android Release 的 P50/P95，不代表真机性能结论。额外的首次 import 仍然可能有加载耗时，页面会显示正常加载提示，并可返回。

## 明暗配色功能

编辑器两页表示“编辑浅色配色 / 编辑深色配色”；实际选择由“舞台浅色外观”控制，页面明确提示当前使用哪一套。保存进入原 profile.themes，当前配色进入 profile.visual.theme，再由 resolveRearStageConfig 和现有发布链路作用到背屏。浏览器回归以不同背景色验证保存、切换、重新进入及最终配置，歌曲身份和歌词保持不变。

取色节流值附带所属配色与颜色项，切换前提交并在卸载时取消计时器，防止快速操作写入错误颜色项。

## 主要文件

- `RearStageAppearancePage.tsx`：统一控件、禁用、备份和加载状态。
- `MobileSettingsLanding.tsx`、`rearControlModel.ts`：安全区、页面宿主、标题与返回。
- `rearControl.css`：页面内滚动、小屏标签、禁用与备份样式。
- `SettingsFrameRateSlider.tsx`、`GraphicsSettingsSubview.tsx`：共用帧率控件。
- `ThemeQuickEditor.tsx`、`VisPlayground.tsx`：保留原编辑能力，新增页面呈现及独立的编辑器界面配色。
- `rearAppearanceModules.ts`：可复用加载结果和现有空闲调度。
- 中英文文案、相关单元与浏览器测试。

未改动音频引擎、播放队列、歌词同步、LSP/Shizuku 服务、首页及底栏。
