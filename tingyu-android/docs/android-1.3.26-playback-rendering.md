# 听屿 Android 1.3.26：连续播放与页面交接修复

## 播放

- 原生 `setSource` 在布局阶段提交新歌，旧 Web 音频桥随后又执行 `pause/load`，会把暂停发给新歌。本次仅在浏览器播放通道保留这段操作，Media3 继续负责自己的歌曲替换。
- 原生事件按歌曲身份和播放意图序号过滤，避免较晚到达的旧准备、暂停、播放事件覆盖新状态。
- 快速切歌时取消尚未发送的旧歌曲命令，清空歌曲后清除身份；释放后的队列只允许停止命令继续完成。
- 不重构 Media3，不改变音源解析、播放内核选择、均衡器兼容路径或背屏歌词协议。

## 页面

- Liquid Glass 的背景捕获节点保持同一个生命周期，不再因控制栏自动隐藏或打开菜单而拆建 AndroidView 的绘制层；保留现有模糊、折射、控件及动效。
- 舞台使用不透明的 WebView 背景清屏；原生设置及其预览仍使用透明背景。只在路由变化时更新，不逐帧请求重绘。
- 原生路由进入首页、资料库、歌单或搜索时，通过同步的路由标记立即隐藏旧歌词画布，React 后续再释放资源。舞台收起动画仍先完成再切换路由。
- 歌词匹配等提示移到舞台歌曲标题下方，保留安全区偏移。

## 验证与限制

- 新增真实原生适配器与音频桥联合测试，连续替换三首来源。修复前换歌多发两次暂停，测试失败；修复后测试通过。
- 39 项相关 JS 回归测试、TypeScript 检查、121 项 Android JVM 测试通过。
- 22 项 Playwright 检查使用 Capacitor/原生事件模拟端口检查八次切源、六次样式/播放设置往返、五次舞台收起/重开、提示与标题边界、隐藏舞台资源释放。原生端口模拟并非 Android 解码或 Compose 像素验证。
- 浏览器实测页面交接保护在 React 卸载之前生效，无未捕获运行时错误。模拟原生页面在浏览器中不绘制，因此浏览器首页空白截图不用于证明 Compose 首页外观。
- 未连接手机。本机模拟器缺少硬件加速驱动，软件启动也未形成可用测试设备，未将其计入通过项。小米 WebView/Compose GPU 合成、系统浮窗、背屏锁屏与真实音源连续播放仍须真机复核。
