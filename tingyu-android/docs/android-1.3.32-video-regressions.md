# 听屿 Android 1.3.32

基于 1.3.31 继续修复本次两段视频与两张截图。版本号 1.3.32，versionCode 56，沿用原签名。未连接用户手机，不移植歌词舞台，不改变歌词动效、背屏避让和控件自动隐藏规则。

## 搜索输入首字后跳页、键盘关闭

旧模型把 landing、suggest、results、查询文字和结果类别拼进原生页面 key。输入第一个字符时 AnimatedContent 会把搜索作为新页面处理，旧 BasicTextField 被销毁，输入法组合状态和焦点随之丢失。

改为同一音乐来源下稳定的搜索页面身份。输入、建议、提交、结果类别仅更新内容，不重新进入页面。歌曲菜单仍是独立页面，保留原有返回行为。

回归覆盖 `w → wo → 我 → 我们的歌 → 提交` 以及结果类别切换；浏览器里的真实 App 原生桥模型在整个流程维持相同 key/session，输入事件和组合状态正确传递。手机输入法的最终表现仍需设备确认。

## 歌词字随机消失再出现

视频逐帧可见：已唱出的字在相邻帧消失再恢复，背景和辅助线仍在，不能仅归因于换句或时钟。此次为参与 Liquid Glass 背景采样的 AndroidView 加入持续存在的独立硬件合成层，避免直接重复使用 WebView 的动态绘制内容；路线切换和控件隐藏时不拆建该节点。仅在使用玻璃采样的 Android 12+ 启用。保留原有模糊、发光、位移、缩放与帧率设置。

该处理参考了上游 AndroidView 与 Backdrop 的合成稳定方案：<https://github.com/Kyant0/AndroidLiquidGlass/issues/82>。上游案例是视频 TextureView，不能据此断言所有 WebView/手机 GPU 均已修复。

本机浏览器逐一运行 15 个顶层样式，未捕获脚本异常；流光与云阶连续检查 76/78 帧，已结束的词未回到隐藏状态。这只能验证浏览器运行逻辑，不能替代录屏手机上的 Android 合成验证。本机 Android 模拟器缺少硬件加速驱动，未声称完成模拟器或真机绘制验证。新增合成层的设备显存、帧时间和耗电也需要复测。

## QQ 歌单使用星海源失败

用用户提供的星海 v3.2.15 请求截图中的《像晴天像雨天》，复现源后端返回“QQ音乐暂时无法获取”；复测还遇到该源的超时和 HTTP 503。

- 首选歌曲所属平台。该通道失败时，通过同一所选脚本的其他已声明平台进行一次有界备用取流；严格匹配歌名、歌手、时长，拒绝翻唱、Live 或明显不同时长。不转回平台原音源或试听，保留 QQ 歌单、收藏、队列身份。
- 按 LX 歌曲信息分别传递 QQ songmid、数字 songId、文件 mediaMid 和 albumMid；备用平台使用它自己的目录标识，不能把 QQ mid 发给酷我。
- 当前播放与下一首预取共用运行器时，全部请求结束后才开始空闲回收。超时已停止的运行器在下一次请求时重新创建，避免连续请求一并失败。
- 启用自定义源时，跳过没有音源归属信息的旧下载音频，避免平台试听缓存覆盖用户选择。
- 保留并记录音源返回的具体失败原因和实际备用平台。音源服务器自身不可用时仍可能失败，本次不保证第三方服务持续在线。

本机真实 QuickJS Worker + 实际远端音源：原 QQ 记录匹配到同名、同歌手、时长 236 秒的酷我记录，浏览器识别媒体时长 236.616939 秒。实际播放进度从头推进至 1.40 秒，跳到 65 秒后继续推进至 66.26 秒，未暂停、未报媒体错误。HTTP 与媒体转发在此测试中由本机代理代替 Android 桥；手机 Media3 与连续多首播放仍需确认。用户脚本未放入源码或 APK。
